Three defects fixed in this session covering the RSI Momentum Scanner, Portfolio Beta grid, and the Portfolio Summary Bar 1 Day Change card.

## Defect 1 — RSI Momentum Scanner: Closed position shown as "Portfolio" in Overbought chain

### Symptom

A ticker (e.g. `PAYPL.TO`) that had been **closed** (sold out) continued to display with `Tracking = Portfolio` badge in the Overbought chain, even though it was no longer an active holding.

### Root Cause

Two code paths both omitted the `TransactionType != "CLOSE"` guard:

1. **Backend** — `ScannerController.GetRsiScan`: queried `PortfolioItems` without filtering closed records. The closed symbol was therefore passed to `IRsiScannerService.ScanAsync` as an active portfolio symbol, causing it to appear in the extra-symbols universe.

2. **Frontend** — `ScannerPageComponent.portfolioSymbols`: built the `Set<string>` from `portfolio.summaries()` without filtering, so closed positions matched in `RsiScannerTableComponent.trackingStatus()`.

### Fix

**`backend/PortfolioManager.Api/Controllers/ScannerController.cs`**

```csharp
// Before
var portfolioSymbols = await db.PortfolioItems
    .Where(p => !p.IsManual)

// After
var portfolioSymbols = await db.PortfolioItems
    .Where(p => !p.IsManual && p.TransactionType != "CLOSE")
```

**`frontend/…/scanner/scanner-page.component.ts`**

```typescript
// Before
() => new Set(this.portfolio.summaries().map(s => s.item.symbol.toLowerCase()))

// After
() => new Set(
    this.portfolio.summaries()
        .filter(s => s.item.transactionType !== 'CLOSE')
        .map(s => s.item.symbol.toLowerCase())
)
```

## Defect 2 — Portfolio Beta: all beta values blank in the grid

### Symptom

The BETA column in the Portfolio grid showed `—` for every ticker. Overriding a value in the input worked, but no fetched (Yahoo Finance) beta was pre-populated for any position. Only positions appearing in the "Top 5 contributors" panel on the Allocation page had populated values, and those were the top 5 by weighted-beta impact — all others remained blank.

### Root Cause

`PortfolioBetaService.CalculateAsync` returned only the top-5 contributors via `.Take(5)`. The `PortfolioBetaStateService.load()` populated `_fetchedBetas` only from `r.topContributors`, so symbols outside the top 5 were never hydrated — `betaForSymbol()` returned `null` → the input showed `—`.

Additionally, user-edited overrides stored in `localStorage` were **not** passed to the backend, so `portfolioBeta` on the summary card did not reflect user edits.

### Fix

**`backend/…/Services/PortfolioBetaService.cs`** — interface and implementation updated:

- `CalculateAsync` now accepts `Dictionary<string, decimal>? betaOverrides`; overrides are applied before the Yahoo Finance fetch (user value wins, no HTTP call needed for overridden symbols)
- `.Take(5)` removed — all contributors returned ordered by weighted-beta impact (descending)

**`backend/…/Controllers/PortfolioBetaController.cs`** — new POST endpoint added:

```
POST /api/portfoliobeta/calculate
Body: { "betaOverrides": { "PYPL": 1.15, "TD.TO": 0.95 } }
```

The existing `GET /api/portfoliobeta` remains unchanged (no overrides).

**`backend/…/Models/PortfolioValueHistory.cs`** — added `PortfolioBetaRequest` DTO:

```csharp
public class PortfolioBetaRequest
{
    public Dictionary<string, decimal>? BetaOverrides { get; set; }
}
```

**`frontend/…/services/portfolio-beta-api.service.ts`**

```typescript
getBeta(betaOverrides?: Record<string, number>): Observable<PortfolioBetaResult> {
    if (betaOverrides && Object.keys(betaOverrides).length > 0)
        return this.api.calculatePortfolioBeta(betaOverrides);   // POST with overrides
    return this.api.getPortfolioBeta();                          // GET (no overrides)
}
```

**`frontend/…/services/portfolio-beta-state.service.ts`**

- `load()` now passes `_betaOverrides` to the API call so the server recomputes Portfolio Beta with user values
- `_fetchedBetas` is now populated from **all** contributors, not just the top 5

**`frontend/…/services/portfolio-api.service.ts`** — two new methods:

```typescript
calculatePortfolioBeta(betaOverrides: Record<string, number>): Observable<PortfolioBetaResult>
recordPortfolioValueNow(): Observable<PortfolioValueHistoryDto>
```

**`frontend/…/allocation-page.component.html`** — label updated from "Top 5 Beta Contributors" → "Beta by Position" (now shows all positions).

## Defect 3 — Portfolio Summary Bar: 1 Day Change card always shows "—"

### Symptom

The "1 Day Change" card on the Portfolio page permanently displayed `—` (dash), regardless of whether the user had portfolio holdings.

### Root Cause — two independent issues

#### 3a. `PortfolioValueHistories` table was missing

The EF migration `20260719000001_AddPortfolioValueHistory` was registered in `__EFMigrationsHistory` but the table had never been physically created in the database (likely due to the DB being set up from SQL scripts rather than EF migrations). Every API call to `GET /api/portfoliovaluehistory/latest` returned HTTP 500.

#### 3b. Frontend logic required exactly 2 records

```typescript
// Before — requires 2 records; uses wrong record when today's snapshot is absent
if (history.length >= 2) {
  this.previousDayValue.set(history[1].totalValue); // always uses [1]
}
```

If the background service had not yet fired (before 4:30 PM ET) and only yesterday's record existed, `history[0]` would be yesterday and `history[1]` would be two days ago — the wrong baseline. With fewer than 2 records the card always showed `—`.

### Fix

**Database** — table created via SQLCMD (already in `02_CreateTables.sql`; was not applied in this environment):

```sql
CREATE TABLE [dbo].[PortfolioValueHistories] (...)
CREATE INDEX [IX_PortfolioValueHistories_RecordedDate] ON ...
```

**Data seeded** — two records inserted for initial operation:

- `2026-07-21`: live portfolio value captured via the new `record-now` endpoint ($802,486.10)
- `2026-07-18`: seed record (previous Friday) with same base value

**`backend/…/Services/PortfolioValueHistoryService.cs`** — interface extended + `RecordCurrentValueAsync()` implemented:

- Queries current live prices from Yahoo Finance for all open positions
- Calculates stocks + cash + options total
- Upserts (removes existing record for date, inserts fresh)

**`backend/…/Controllers/PortfolioValueHistoryController.cs`** — new endpoint:

```
POST /api/portfoliovaluehistory/record-now
```

Returns the saved `PortfolioValueHistoryDto`. Call this whenever you need to seed or update today's value manually (e.g. if the background service was not running at 4:30 PM ET).

**`frontend/…/portfolio-summary-bar.component.ts`** — logic rewritten:

```typescript
// After — handles 1 record correctly; checks which record is "today"
const todayDate = new Date().toISOString().split("T")[0];
const isFirstRecordToday = history[0].recordedDate === todayDate;

if (isFirstRecordToday && history.length >= 2) {
  // history[0] = today's EOD snapshot → use history[1] as previous-day baseline
  this.previousDayValue.set(history[1].totalValue);
} else if (!isFirstRecordToday) {
  // Today's snapshot not saved yet (before 4:30 PM ET) → history[0] is yesterday
  this.previousDayValue.set(history[0].totalValue);
}
// If only 1 record and it is today: cannot compute change — card stays null
```

### Background Service Behaviour (no change required)

`PortfolioValueEodBackgroundService` fires at **4:30 PM ET** on weekdays. It skips dates that already have a record (`ExistsForDateAsync`). Call `POST /api/portfoliovaluehistory/record-now` if the server was not running at 4:30 PM — the background service will correctly populate every subsequent trading day automatically.
