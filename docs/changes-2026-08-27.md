# Portfolio Manager — Changes 2026-08-27

All changes are live. Backend running on port 5000, frontend on port 4200.

---

## 1. Unified Auto-Refresh (App Auto-Refresh)

### What changed

- Replaced the separate Dashboard/Portfolio and Watchlist auto-refresh intervals with a single **App Auto-Refresh** interval that refreshes portfolio, watchlist, and dashboard together in one backend call.
- New `POST /api/data/refresh` endpoint: fetches portfolio + watchlist quotes in parallel (2 Yahoo Finance batch calls), saves both snapshots, rebuilds dashboard once.
- Non-blocking **Monarch-style progress overlay** appears in the bottom-right corner during refresh, showing 3 steps and a Cancel button.
- All per-page Refresh buttons (Dashboard, Portfolio, Watchlist) now invoke the same global refresh.

### How to test

1. **Config page** → Configuration → Scanner tab → "Auto-Refresh Intervals" section
   - Should show **2 dropdowns only**: RSI Scanner auto-refresh + App auto-refresh interval
   - (Previously had 3: RSI Scanner, Dashboard/Portfolio, Watchlist — separately)
   - Set App auto-refresh to 1 min

2. **Wait 1 minute** → the progress overlay should appear in the bottom-right corner
   - Shows: "Fetching portfolio & watchlist quotes" → "Rebuilding dashboard snapshot" → "Updating all views"
   - All three steps complete and the card auto-hides after 5 seconds

3. **Manual refresh** → click Refresh on Dashboard page
   - Same overlay appears
   - Open Network tab in DevTools → only ONE request to `POST /api/data/refresh` (no separate GET /api/stocks/quotes or GET /api/watchlist)

4. **Cancel refresh** → click Refresh, immediately click the ✕ in the overlay
   - Overlay disappears; no data change

5. **Backward compatibility** → if a previous session had separate intervals saved, they are automatically migrated to `appRefreshSeconds` on first load (no manual action needed)

## 2. Watchlist — Surgical Role/Tier/Earnings Updates

### What changed

- Changing the **Role** dropdown (top colored — Core/Strategic/Swing/Speculative) → 1 PATCH to DB, instant in-memory update. No Yahoo Finance call.
- Changing the **Monitoring Tier** dropdown (bottom gray — Active/Strategic/Universe) → same: 1 PATCH, no full refresh.
- Changing **Earnings Date** → same: 1 PATCH, no full refresh.
- Previously, tier and earnings date changes triggered a full Yahoo Finance re-fetch for all 146 symbols.
- Added `trackBy` on the grid table so only the changed row re-renders.

### How to test

1. **Open DevTools → Network tab** (filter by Fetch/XHR)
2. Go to Watchlist page
3. Change the **bottom gray dropdown** (tier) on any symbol from Strategic → Active
   - Network tab: should see exactly **1 PATCH** to `/api/watchlist/{id}/tier`
   - Should NOT see `GET /api/watchlist`
   - Active count in the tab bar (e.g. "Active 6/25") should update immediately

4. Change an **Earnings Date** manually on any symbol
   - Network tab: should see exactly **1 PATCH** to `/api/watchlist/{id}/earnings-date`
   - Should NOT see `GET /api/watchlist`

5. Change the **top colored dropdown** (role) on any symbol
   - Same: 1 PATCH to `/api/watchlist/{id}/role`, no full reload

6. **No screen disruption**: none of the above should cause a blank/loading state in the other columns (Trend Setup, FIB Zone, etc.)

## 6. Dashboard — Sector Allocation Fixes

### What changed

#### a) Cash included in denominator; Options excluded

- The "Actual %" column in By Sector now uses **(stocks value + cash) as the denominator** instead of stocks only.
- Items with `HoldingRole = "Options"` are excluded from the sector calculation.
- Effect: if you hold a large cash balance, all sector percentages will be lower (more realistic — cash is part of your deployed capital).

#### b) Sortable columns

- All column headers in the Sector table are now clickable: **Sector · Actual · Target · Delta**
- Default sort: **Actual descending** (highest allocation at the top)
- Active sort column shows an arrow indicator (↑ or ↓)
- Clicking the active column toggles direction; clicking a new column sets it as active

### How to test

1. Go to **Dashboard** → scroll to "Allocation vs Targets" → click **By Sector** tab
2. Check the **sort arrows**: "Actual" column should have a ↓ arrow; rows ordered highest % first
3. Click **Sector** header → rows sort alphabetically A→Z, arrow appears on Sector column
4. Click **Sector** again → sorts Z→A
5. Click **Delta** → sorts by delta value
6. If you have a significant cash position: the actual % values should be lower than before (reflecting cash in denominator)

## 8. Action Center (was "Portfolio Actions")

### What changed

This section was completely redesigned. The previous version sent every signal through the same vocabulary regardless of whether you own the stock.

**Key design change:**

- **Holdings** and **Watchlist** candidates are now shown in separate sub-sections with their own column header and vocabulary
- Role (Core/Strategic/Swing/Speculative) now determines what a technical condition _means_
- Three priority tiers: **REQUIRED** (thick border) · **DEVELOPING** (thin border) · **INFORMATIONAL** (dimmed)

**New Holdings vocabulary (you own the stock):**
| Label | When |
|---|---|
| ADD WATCH | Core, oversold, bullish reversal, sector not overweight |
| HOLD — SECTOR FULL | Core, oversold, bullish, but sector is overweight |
| REVERSAL WATCH | Swing/Speculative, oversold, bullish momentum |
| BUY WATCH | Strategic, oversold, bullish |
| EXIT REVIEW | Swing, oversold, still falling, Trend Damage → **REQUIRED** |
| RISK REVIEW | Speculative, oversold, still falling, Trend Damage → **REQUIRED** |
| HOLD / REVIEW THESIS | Strategic, oversold, Trend Damage |
| HOLD — WAIT | Core, oversold, Trend Damage (Core does NOT exit on technical weakness) |
| HOLD — WEAKNESS | Any, oversold, falling (no Trend Damage) |
| TRIM | Swing/Spec, overbought, bearish → **REQUIRED** |
| TRIM WATCH | Core/Strategic, overbought, bearish → DEVELOPING |
| HOLD — EXTENDED | Any, overbought, not yet bearish |
| DO NOT CHASE | Chase risk flag set → **REQUIRED** |

**New Watchlist vocabulary (you don't own it):**
| Label | When |
|---|---|
| ENTRY CANDIDATE | Oversold, confirmed Bull Turn, no Trend Damage → **REQUIRED** |
| STARTER ENTRY | Oversold, Stabilizing, no Trend Damage → **REQUIRED** |
| BUY WATCH | Oversold, bullish, but Trend Damage present |
| WAIT FOR REVERSAL | Oversold, still falling, no Trend Damage |
| AVOID — TREND DAMAGE | Oversold, still falling, Trend Damage |
| WAIT FOR PULLBACK | Overbought (extended — wrong time to enter) |

### How to test

1. Go to **Dashboard** → scroll to **Action Center** panel (was "Portfolio actions")

2. **Section headers**: you should see two sub-sections:
   - Blue header: "Holdings — Position Action" (for stocks you own, with P badge)
   - Purple header: "Watchlist — Entry Status" (for watchlist-only items, with W badge)

3. **Count bar**: at the top of the panel, e.g. "3 Action Required · 6 Developing · 12 Informational"

4. **Priority visual intensity**:
   - REQUIRED rows: thick green/red/orange left border, full brightness
   - DEVELOPING rows: thin border, slightly dimmed
   - INFORMATIONAL rows: no border, noticeably dimmed (65% opacity)

5. **Vocabulary check — Holdings**:
   - Any Core holding with Trend Damage + Still Falling → should show **HOLD — WAIT** (not the old "REVIEW — TREND DAMAGE")
   - Any Swing holding with Trend Damage + Still Falling → should show **EXIT REVIEW** (REQUIRED)
   - Any holding with Overbought + Swing/Speculative + Bearish → should show **TRIM** (REQUIRED)

6. **Vocabulary check — Watchlist**:
   - Any watchlist-only symbol with Overbought (RSI > 75) → should show **WAIT FOR PULLBACK** (not "TRIM / TAKE PROFIT")
   - Watchlist symbol with Oversold + Bull Turn + no Trend Damage → should show **ENTRY CANDIDATE** (REQUIRED)

7. **Column headers differ by section**:
   - Holdings table last column: "Position Action"
   - Watchlist table last column: "Entry Status"

8. **Verify these specific labels no longer exist anywhere**:
   - ~~REVIEW — TREND DAMAGE~~
   - ~~TRIM / TAKE PROFIT~~ (on watchlist items)
   - ~~HOLD / TRIM WATCH~~ (replaced by clearer labels)
